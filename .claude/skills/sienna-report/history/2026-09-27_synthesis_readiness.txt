3. NEEDS A DECISION BEFORE OR DURING SYNTHESIS (structural; not changed)
   a. Weight cache (128 KiB fp32 / 64 KiB bf16 at N=16; 4x at N=32): must be SRAM. The broadcast reads N/T full
      rows (N words each) per cycle, so bank it by row: N/T banks, one N-word row per bank per cycle. The RTL assumes
      a one-cycle read; at 950 MHz a macro this size may need two, which costs one broadcast cycle per set (not
      throughput, since broadcast takes T+2 of the N cycles a set has).
   b. Result SRAM (MeshOutputSram): one array with one write port per reducer ((N/T)^2 = 16) and a NUM_LANES-word
      wide read. As written that is per-word write decoding across 16 ports plus 32 read muxes. Each reducer writes
      only its own tile, so a bank per tile removes the write-port logic; the wide read then needs a small crossbar.
   c. Activation buffer (gpnae_out_mem, 2 KiB at N=16): the pooling dispatcher reads NUM_LANES words per cycle at
      computed addresses, i.e. 32 read ports of 512:1 on 32-bit words. Fine for timing, heavy for area; a
      per-lane layout matching the dispatch order would cut it.
   d. Array operand banks: every array keeps its own copy of the A rows it shares with its tile row (and B with its
      column): 16 KiB at N=16 but 128 KiB at N=32, fp32. Sharing one copy per tile row/column saves about 3/4 of
      it at T=4.
   e. GPNAE (published TYTAN code, reported rather than changed): RAM.v resets its output register synchronously to
      X while the same reset is asynchronous elsewhere (lint SYNCASYNCNET); ROM.v loads each lane's 32-entry
      coefficient ROM with $readmemb, which ASIC flows do not turn into a ROM (use a constant table or ROM macro);
      the 32 lanes hold identical ROMs that could be one.
   f. ArithmeticLibrary R4Booth: blocking assignments inside always_ff (style; synthesizes correctly).

4. LIKELY CRITICAL PATHS (by inspection; to confirm with the first timing report)
   - Arithmetic units: the same fp32 multiplier/adder library met 950 MHz in FreePDK45 in the published TYTAN work;
     fpMulWiden does an 8x8 (bf16) or 11x11 (fp16) product in one stage.
   - Array 'set final' AND: every PE's per-bank final flag ANDed across the mesh, feeding reduce_start in the same
     cycle: 256 inputs at N=16, 1024 at N=32. Register it if timing needs (one cycle of latency).
   - Weight-cache read (3a) and the result SRAM ports (3b): memory access, not logic, sets the limit.
   - Dispatcher address and read (3c): about 9 mux levels after a small add; expected to fit.
