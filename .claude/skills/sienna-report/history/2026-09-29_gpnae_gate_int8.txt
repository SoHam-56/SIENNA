FINDINGS (reported, not changed)
   P-1  last_i with the last wr_en: G_IDLE reads the FIFO count before that write, so a group of n splits into n-1 and a
        one-element group (an extra group pass), and a lone element written with last_i waits until the next last_i.
        Outputs stay correct and in order. The float lane has the same G_IDLE. sienna_top raises last_i the cycle after
        the last write (read, not run), so SIENNA does not hit it today.
   P-2  The published float lane's G_RUN has the one-element-group hang Task 11 fixed in the int8 lane (reported by
        Task 11; the stream's RED run shows the int8 lane hangs the same way without the fix).
   T-1  With 32 signals per batch the FIFO fills, and the TB's zero-delay write drive tripped "Writing when module is
        full!" at the 32nd write of every batch (sienna_jobs/runs/i12_fulldiag: 1480 of 1480 batches; a plain clocked
        monitor saw no write while full, and all outputs were exact). int8 now drives 1 ns after each edge; float
        unchanged. Float runs use 30 signals, so the float TB never fills the FIFO and never exercised this assertion.
